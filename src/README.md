# src/

The Astro site: pages, layouts, components, styles and the catalogue data.
Read this before changing anything here. The rules for the content
(`public/tex/`) and for `src/data/` are in the root `AGENTS.md`.

## Site structure and presentation

The home page contains the Further Maths strand picker at `/#further-maths`, linking directly to `/further-maths/core-pure`, `/further-maths/further-mechanics` and `/further-maths/additional-pure`. The picker, the header and the 404 page list a strand only once it has a row, and until then its page is `noindex`; a strand page lists only the sections that have a row, in its sidebar and topic picker too. The legacy `/further-maths` route redirects to `/#further-maths` (an HTML redirect page on the static host). The shared header links directly to the resource listings; from 1024px up it is a single sticky row whose height is the `--header-h` token, and the strand sidebar (sticky, independently scrollable) and anchor offsets (`--anchor-offset` → `scroll-padding-top`) derive from it. Below 1024px the header scrolls away and strand pages pin the board/topic pickers instead. All pages share one `.page-container` width. Internal links open in the same tab; only the viewer's raw "Open PDF" and external profile links open new tabs. A pack's documents are always listed in the order Questions | Mark scheme | Solutions, on its strand-page card (`ResourcePairCard.astro`) and in the viewer's segmented control (`familyInOrder` in `resources.ts`); a pack without a mark scheme shows Questions | Solutions, and a TMUA paper Questions | Answer key | Solutions. From 1024px the viewer shows any two of a pack's documents side by side (`src/scripts/viewer.ts`): each pane has its own picker, picking the other pane's document swaps the two, and a swap button sits on the divider. Side by side opens with the questions on the left and the page opened on the right (on the questions page, the document last chosen for the right pane, else the solutions). The layout is in the address as `?left=<type>&right=<type>` (`?split=1` still opens the starting layout), and the browser remembers under `resources-viewer-layout` whether side by side was on and what was on the right, so it carries to the next pack. Each document has its own iframe, loaded when first shown and placed by `data-slot`, never moved, so a swap doesn't reload a PDF. Below 768px the viewer is the "Open PDF" page, unaffected by any of this. The board filter dims non-matching booklets (they stay in place and clickable) and updates per-topic counts. Its menu lists each board with its code from `src/data/exam-boards.json` (the qualification's in Core Pure, the paper's in Further Mechanics and Additional Pure) beside its label; the filter status line ends with the chosen board's breadcrumb (awarding body, then the qualification, or in Further Mechanics and Additional Pure the paper, whose code already names the qualification). The pills under a pack show board labels only, never codes. Site-wide presentation lives in `src/styles/global.css` with the palette and font tokens declared in its `@theme` blocks: warm white, dark ink, burgundy accents, serif headings and ruled resource lists. Light mode is the default. `ThemeToggle.astro` switches the shared CSS colour variables, with the explicit choice persisted in `localStorage` under `resources-theme`; `Layout.astro` restores it before paint. The document viewer's header also exposes the toggle.

## Mobile site behaviour

Below 1024px, Further Maths pages use labelled native exam-board and topic selects; the desktop sidebar controls remain synchronised. The board options keep their plain labels (a code would cut the closed select short); the chosen board's code follows the select's "Exam board" label, inside the pinned bar, and its breadcrumb ends the status line. Board selection dims non-matching booklets, preserves the topic fragment, and persists per strand. Topic selection updates the fragment and focuses the destination heading.

Below 768px a pack card's document links sit on their own line under its title and pills, 44px tall; below 360px they tighten so Questions | Mark scheme | Solutions still fit one line at 320px, and narrower still they wrap rather than scroll the page sideways. Mobile header tuition navigation is available in the footer; the theme toggle uses its accessible label with a compact icon.

## Search metadata

`Layout.astro` supplies absolute, trailing-slash canonical URLs and Open Graph/Twitter metadata; a page can pass `canonicalPath` to name another page as its canonical and `og:url`, which the viewer does for a row with `canonicalId` (a pack's second publication), naming its home row's `/view/<id>/`. Pages share the square logo by default; a page can pass a wide `shareImage` (which also switches the Twitter card to `summary_large_image`). TMUA pages pass `TMUA_SHARE_IMAGE` from `resources.ts`, built from `og-images/`; it deliberately states no counts so it cannot go stale. The TMUA listing's description is built from `getTmuaStats()` (sets, papers, questions, questions with worked solutions), so its counts update with the catalogue. Internal page links must also end in `/` (e.g. `/tmua/`, `/view/<id>/`) so they match the canonical and avoid the host's 301; `trailingSlash: 'always'` in `astro.config.mjs` makes the dev server 404 on a missing slash. Document titles distinguish questions, answer keys, mark schemes and worked solutions. Each old `/source/<id>/` address is a redirect page to `/view/<id>/` (`src/pages/source/[id].astro`, over the fixed id list in `src/data/source-redirects.json`), which carries the refresh, `noindex` and the canonical; the sitemap excludes those pages, the 404 page, the legacy Further Maths redirect, the page of a strand with no row yet and the view page of every row with `canonicalId` (`astro.config.mjs` reads the rows and `topics.json` for this). `public/robots.txt` points crawlers at the sitemap index.
